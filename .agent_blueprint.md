# 1. USER INTENT & WORKFLOW GOAL
The user needs a fully functional, production-ready geometry creation and file import workflow in the Z-CAM web application.
First, the file import mechanism must bridge the web environment to the user's native OS file system, allowing them to browse and select local CAD files (e.g., STEP, DXF) using a native file picker (like Windows Explorer or macOS Finder) instead of failing silently.
Second, the geometry creation workflow must be overhauled to match a Mastercam-style "Designing a Part" interactive experience. Instead of dropping static wireframe elements blindly, the user must see a live, interactive "rubber-band" preview of lines, arcs, and points attached to their cursor. This includes dynamic coordinate feedback, interactive snapping (AutoCursor-style), and the ability to type exact dimensions or coordinates during placement before committing the geometry to the document.

# 2. DESIGN TOKENS & GEOMETRY INVARIANTS
- **Live Preview Geometry (Rubber-banding)**: Stroke width `1.5`, Color `Color32::from_rgb(0, 255, 255)` (Cyan) to match standard CAM active entity highlighting.
- **Snapping Indicators (AutoCursor)**:
  - Endpoint: Square, `4.0` px radius, `Color32::GREEN`.
  - Midpoint: Triangle, `4.0` px radius, `Color32::GREEN`.
  - Center: Circle, `4.0` px radius, `Color32::GREEN`.
- **Committed Wireframe**: Stroke width `1.0`, Color `Color32::from_rgb(0, 255, 0)` (Green) for standard wireframe.
- **Input Fields**: Map dimensional override inputs to `crates/ui-egui/src/ui_kit/fields.rs` standard numeric inputs.
- **Tolerances**: Geometry snap tolerance is tightly bound to `0.001` document units in 3D space, or `8.0` logical pixels in screen space.

# 3. TECHNICAL IMPLEMENTATION SPEC
- **Web Native File Picker**:
  - Target: `apps/solidcraft-web/src/files.rs` and `crates/ui-egui/src/file_picker.rs`.
  - Implementation: Use `wasm-bindgen` and `web_sys` to dynamically create an `<input type="file" style="display:none">` DOM element when the import command is invoked.
  - Wire the `onchange` event to a `FileReader` that reads the file as an `ArrayBuffer`, converts it to a `Uint8Array`, and sends the byte stream to the `cam-workspace` document loader via `apps/solidcraft-web/src/api.rs`.
- **Interactive Geometry State Machine**:
  - Target: Create `apps/cam-workspace/src/interactive_geom.rs`.
  - Define `pub enum WireframeTool { None, Line(LineState), Arc(ArcState), Point(PointState) }`.
  - Define `LineState { p1: Option<Point3d>, current_pos: Point3d }`.
  - Integrate into `apps/cam-workspace/src/viewport.rs` inside the main event loop to intercept `PointerMoved` and `PointerButton::Primary` clicks.
- **Snapping & Rubber-Banding**:
  - Target: `apps/cam-workspace/src/viewport.rs`.
  - Utilize `crates/sketch/src/cursor.rs` and `crates/geom/src/tess/` to project screen coordinates to the active 3D construction plane (Z-depth).
  - During the `PointerMoved` event, query the Solidcraft document (`crates/doc/src/document.rs`) for nearest vertices/edges to populate the snap point.
  - Draw the temporary geometry using `egui::Painter` overlay on the viewport widget.
- **Coordinate Data Entry (AutoCursor)**:
  - Target: `apps/cam-workspace/src/left_manager.rs` or a floating egui window in `apps/cam-workspace/src/viewport.rs`.
  - Expose bound `f64` values for Length, Angle, X, Y, Z. When a user types in these fields, lock that axis/dimension in the `WireframeTool` state machine so the rubber-band strictly obeys the override constraint.
- **Commit Geometry**:
  - When the final click occurs, dispatch the creation command using `crates/engine/src/cmd/sketch_create.rs` and `crates/sketch/src/construct.rs` to mutate the document and persist the wireframe.
