# 1. USER INTENT & WORKFLOW GOAL
- Remove the "Alignment" dropdowns entirely from the Coordinate System (CS) Create/Edit dialog to enforce pure 3D interaction.
- Refine Dynamic Gnomon (DG) hit-testing to strictly separate Cone (arrowhead), Shaft (line), and Origin (sphere) clicks.
- Implement click-to-toggle 3D snapping modes: clicking the Cone enters `AxisOrbit` mode (orienting the axis to snapped geometry), clicking the Origin enters `OriginSnap` mode (moving/snapping the entire DG), with a second click committing the placement.
- Fix floating incremental input boxes on the DG (triggered by Shaft clicks) so they start empty/zeroed, immediately grab keyboard focus, and do not prematurely dismiss when clicked inside.
- Suppress the viewport's drag-selection marquee when hovering or interacting with the DG.
- Update the 'Convert to Named View' action on a Coordinate System to non-destructively generate a view named `CS:<CS Name>`, appending numeric suffixes `(1)`, `(2)`, etc. if duplicates exist.

# 3. TECHNICAL IMPLEMENTATION SPEC
- **CS Dialog (`dialogs_cam.rs`)**:
  - Locate the `choice_row` calls for primary/secondary alignment modes. Delete them.
  - The dialog should now only contain Name and Origin fields (and potentially axis flips if pre-existing, but strictly no new dropdowns).
- **Dynamic Gnomon Interaction (`dynamic_gnomon.rs`)**:
  - **Hit Testing Breakdown**: When checking for clicks, prioritize Cone > Origin > Shaft to prevent overlapping bounding box issues.
  - **Interaction State Enum**: Ensure a state machine exists similar to `enum GnomonState { Idle, OriginSnap, AxisOrbit(Axis), Input(Target) }`.
  - **Toggle Logic**: On left-click:
    - If `Idle` and clicked Cone(axis) -> transition to `AxisOrbit(axis)`.
    - If `Idle` and clicked Origin -> transition to `OriginSnap`.
    - If `Idle` and clicked Shaft(axis) -> transition to `Input(RelativeTransl(axis))` and clear/zero the buffer.
    - If `AxisOrbit` or `OriginSnap` and user clicks in viewport -> apply coordinates/orientation to CS and transition to `Idle`.
  - **Input Box Focus & Dismissal**:
    - When `Input` state begins, issue `ui.memory_mut(|mem| mem.request_focus(text_edit_id));` (or `response.request_focus()`).
    - Only transition out of `Input` state if `ui.input(|i| i.key_pressed(egui::Key::Enter))` (commit), `egui::Key::Escape` (cancel), or if there's a click *outside* the popup's exact `response.rect`.
- **Marquee Suppression (`viewport.rs`)**:
  - Add a method to the DG struct like `pub fn blocks_viewport_marquee(&self) -> bool` (returns true if hovered, dragging, or in an active Snap/Input state).
  - Wrap the marquee `egui::PointerButton::Primary` drag initialization check in `!dg.blocks_viewport_marquee()`.
- **Named View Conversion Naming (`cam_coordinate_system.rs` or related cmd)**:
  - When creating a Named View from a CS:
    - Base name: `let mut name = format!("CS:{}", cs.name);`
    - Check dictionary: `let mut counter = 1; while session.document().named_views.contains_key(&name) { name = format!("CS:{} ({})", cs.name, counter); counter += 1; }`
    - Create the view with `name` and do not delete the original CS.
