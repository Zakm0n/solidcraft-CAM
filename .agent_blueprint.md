# 1. USER INTENT & WORKFLOW GOAL
- **Browser & Context Menus**: Move Coordinate System (CS) entities strictly into the 'Coordinate Systems' browser folder (removing them from 'Origin'). Enable full renaming and implement a right-click context menu (Show/Hide, Create Sketch, Edit Feature, Delete, Rename, Convert to Named View). 
- **Plane to CS**: Add a "Convert to Coordinate System" option to Plane features in the browser, initializing a CS with the Plane's orientation and activating Origin Snap Mode.
- **Dynamic Gnomon (DG) Visuals**: Prevent DG interaction from triggering the viewport's drag-selection marquee. Render 'X', 'Y', 'Z' labels beyond the cones. Draw rotation wheels locally (respecting the DG's current rotated frame).
- **DG Behaviors**: 
  - Clicking the origin enters Origin Snap Mode (snapping to vertices, points, midpoints, circle centers, face centroids). 
  - Snapping to a face centroid auto-aligns the Z-axis to the face's outward normal.
  - Clicking an axis shaft or rotation wheel opens a floating text input for relative distance/angle adjustments.
  - Clicking a cone enters Axis Orbit Mode, snapping the selected axis to target points.

# 3. TECHNICAL IMPLEMENTATION SPEC
- **Browser Filtering**: In `browser_model.rs` or `cam_browser.rs`, ensure `NodeType::CoordinateSystem` does not populate under `NodeType::OriginFolder`.
- **Context Menus**: Use `crate::ui_kit::Menu` for the CS right-click menu. Route to existing commands:
  - Create Sketch -> `app.start_with(sketch.create, ...)`
  - Delete -> `app.run(solid.delete, ...)`
  - Rename -> trigger inline browser rename state.
  - Convert to Named View -> `app.run(view.named.create, ...)`
  - Edit Feature -> `app.start_with(cam.coordinate_system.edit, ...)`
- **Plane to CS**: In Plane's context menu, add an entry calling `app.start_with(cam.coordinate_system.create, { orientation_from: plane_id, snap_mode: true })`.
- **DG Pointer Capture**: In `dynamic_gnomon.rs`, use `response.interact(...)` or check `response.hovered()` and `ui.input(|i| i.pointer.primary_clicked())` to `response.mark_changed()` and consume the event so `viewport.rs` sees `response.consumed() == true`.
- **DG Visuals**: 
  - Use `ui.painter().text(...)` for 'X', 'Y', 'Z' labels. 
  - Colors strictly via `crate::theme::Tokens`. 
  - Rotation wheels: Generate a 3D circle in the local X-Z, Y-Z, X-Y planes using the DG's transform matrix, projecting to 2D screen space.
- **DG Snap & Relative Entry State**: 
  - Introduce `enum GnomonActiveState { Idle, OriginSnap, AxisOrbit(Axis), RelativeInput { axis_or_ring: Id, pos: Pos2 } }`. 
  - Hovering/snapping uses exact geometry via `Session` lookups (face centroids, edge midpoints, circle centers).
  - Face auto-normal: Extract face surface normal at the centroid, set Z-axis, orthogonalize X and Y using standard cross products.
