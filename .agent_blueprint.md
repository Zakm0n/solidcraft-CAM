# 1. USER INTENT & WORKFLOW GOAL
The objective is to deeply integrate the foundational structural layout for the **Z-CAM** expansion directly into SolidCraft. The user experience includes:
- **Application Branding:** Top-level application names reflect "Z-CAM" while maintaining binary/file compatibility.
- **Workspace Navigation:** A refined Workspace dropdown featuring only 'Design', 'Render', 'CAM', and a disabled 'Machine Simulation'.
- **CAM Toolbar:** Switching to the CAM workspace sets the 'Toolpath' tab as the default, housing a new `Create Coordinate System` command and stub groups for future toolpath operations.
- **Coordinate Systems:** A new architectural CAM object defining machining origins. They appear in the 3D viewport as XYZ gnomons and are listed in the Browser under both 'Planes' and a dedicated 'Coordinate Systems' folder.
- **Toolpaths Browser:** A secondary bottom-left tree panel dedicated to CAM operations that only appears when the CAM workspace is active.

# 3. TECHNICAL IMPLEMENTATION SPEC

**A. Message Catalogs & Glossary**
`assets/locales/pending/zcam.json` (maps `"en": { ... }`):
- `ui.workspace.cam`: "CAM"
- `ui.workspace.machine_simulation`: "Machine Simulation"
- `ui.tab.toolpath`: "Toolpath"
- `ui.browser.coordinate_systems`: "Coordinate Systems"
- `ui.cam.toolpaths`: "Toolpaths"
- `cmd.cam.coordinate_system.create`: "Coordinate System"
- `help.cam.coordinate_system.create`: "Creates a programmable machining origin and XYZ orientation.\n\nUse this to define where the machine zero is located on the stock."

**B. UI Workspace & Toolbar (L5 `ui-egui`)**
- `Workspace` enum: Retain `Design`, `Render`, add `Cam`, `MachineSimulation`.
- `toolbar.rs`: When `Workspace::Cam`, inject a `Toolpath` tab group as the first element. Register the `cam.coordinate_system.create` command here. Add visual empty stubs for "2D Milling" and "3D Milling" using standard empty layout containers (no raw egui frames).

**C. Core Data & Engine Commands (L2 `doc`, L4 `engine`)**
- `doc`: Add `CoordinateSystem` entity tracking `origin`, `x_axis`, `y_axis`, `z_axis` (arrays of `[f64; 3]`). Add pending format upgrade to store this.
- `schema/cam_coordinate_system.rs`: Define `Contract` (input params for placement) and `Output` schemas.
- `cmd/cam_coordinate_system.rs`: Implement `CommandSpec` for `cam.coordinate_system.create`. Validate inputs, store entity in session document.

**D. Browser Integration & Panel Layout (L5 `ui-egui`)**
- `browser.rs`: Fetch `CoordinateSystem` entities. Inject them into the existing 'Planes' tree node, and create a new parallel top-level folder 'Coordinate Systems'.
- `timeline_left.rs` / `viewport_layout.rs` (Sidebar container): Conditionally check if `workspace == Cam`. If true, split the vertical space. Top half uses existing Browser `Panel`. Bottom half uses `crate::ui_kit::Panel::new("ui.cam.toolpaths")` wrapping a `Container` to host the upcoming CAM toolpath setups.

**E. 3D Viewport Gnomon (L5 `ui-egui`)**
- Intercept 3D drawing (likely in `crates/ui-egui/src/viewport.rs` or `body_gizmo.rs`).
- Iterate over document coordinate systems. Render origin points and three short line segments along X (Theme red), Y (Theme green), and Z (Theme blue) axes mapped using `crate::theme::Tokens`. Ensure lines are transformed to world space.
