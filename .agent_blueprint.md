# 1. USER INTENT & WORKFLOW GOAL
- Prevent pressing Enter or Escape inside the Dynamic Gnomon's floating incremental value box from mistakenly submitting or closing the parent Coordinate System (CS) Create/Edit dialog. 
- Ensure that the contextual 'Sketch' toolbar tab is enabled, automatically selected when editing a 2D sketch from inside the CAM workspace, and returns to the CAM tab upon exiting the sketch.

# 2. SOLIDCRAFT LAYER COMPLIANCE
- `crates/ui-egui/src/dynamic_gnomon.rs` (Modify: Add key consumption to the floating incremental input box).
- `crates/ui-egui/src/dialogs_cam.rs` (Modify: Guard CS dialog submission against Enter/Escape when the Gnomon input is active).
- `crates/ui-egui/src/toolbar.rs` / `crates/ui-egui/src/workspace.rs` (Modify: Add visibility and auto-selection of the Sketch tab while in the CAM workspace).

# 3. TECHNICAL IMPLEMENTATION SPEC
- **Dynamic Gnomon Key Guard:**
  - In `crates/ui-egui/src/dynamic_gnomon.rs` where the relative/incremental input box is rendered, inject `ui.input_mut(|i| i.consume_key(egui::Modifiers::NONE, egui::Key::Enter))` and `egui::Key::Escape` whenever the floating text field is focused or submitted.
  - Expose an indicator (e.g., `is_incremental_input_active()`) or rely on `ui.ctx().wants_keyboard_input()` to indicate focus.
- **Coordinate System Dialog Guard:**
  - In `crates/ui-egui/src/dialogs_cam.rs` for the CAM Coordinate System dialog, wrap the Enter-to-commit and Escape-to-cancel handlers to ignore the key events if the Dynamic Gnomon's floating input was active on this frame.
- **Contextual Sketch Toolbar in CAM:**
  - In `crates/ui-egui/src/toolbar.rs`, locate the logic that yields available toolbar tabs for the current workspace. Ensure `Tab::Sketch` is returned when `session.sketch_active()` is true, even if `workspace == Workspace::Cam`.
  - Add or update the transition tracking: if `session.sketch_active()` changes from `false` to `true`, auto-select `Tab::Sketch`. If it changes from `true` to `false` while in the CAM workspace, auto-select `Tab::Cam` (or equivalent CAM main tab).

# 4. AUTONOMOUS MILESTONE PHASES

## Phase 1: Dynamic Gnomon Input Key Event Isolation
- Modify `crates/ui-egui/src/dynamic_gnomon.rs` to intercept and fully consume the `Enter` and `Escape` key events when the incremental input popup is active and focused.
- Update `crates/ui-egui/src/dialogs_cam.rs` to verify that Enter/Escape keypresses are completely ignored by the Coordinate System dialog when the Gnomon input is taking keyboard focus.
- Run `cargo check --workspace` and `cargo xtask ui-containers`.

## Phase 2: Contextual Sketch Toolbar Activation in CAM Workspace
- Modify `crates/ui-egui/src/toolbar.rs` (or equivalent tab/workspace file) to conditionally render the `Sketch` tab when `session.sketch_active()` is true within the CAM workspace.
- Implement the tab auto-switch logic: automatically focus the Sketch tab upon entering a sketch, and restore the primary CAM tab upon exiting the sketch.
- Run `cargo check --workspace` and `cargo xtask ui-containers`.
