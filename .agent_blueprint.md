# Z-CAM Implementation Plan: 2D Contour Toolpath

**Epic/Milestone:** Implement 2.5D Contour Machining Toolpath (Command, Schema, UI, and Viewport Integration)

This blueprint provides the exact file-accurate steps to implement the foundational 2D Contour toolpath operation in Z-CAM. The implementation strictly follows the SolidCraft architecture layer constraints and UI container rules.

## Phase 1: Document Persistence & Engine Schemas

In this phase, we establish the core data model and API contracts for the 2D Contour Toolpath. 

**Files to Modify/Create:**
*   `crates/doc/src/cam.rs`
    *   **Action:** Add `CamContour2d` to the persistent document data structures (likely inside an existing `CamOperation` enum or as a new feature struct).
    *   **Fields:** `target_edges: Vec<EntityId>`, `tool_id: Uuid`, `clearance_height: f64`, `bottom_depth: f64`, `stepdown: f64`.
*   `crates/engine/src/schema/cam_toolpath.rs`
    *   **Action:** Define the exact JSON-serializable input parameters and output schema for the engine.
    *   **Implementation:**
        *   Create `pub struct CamContour2dParams` with typed references (`EntityRef` for edges, `Uuid` for tool).
        *   Create `pub struct CamContour2dOutput` containing the generated polyline waypoints (`Vec<Point3>`).
        *   Register the schemas using the engine's `checked!` macro.
*   `assets/locales/pending/zcam.json`
    *   **Action:** Add English localization entries (strict English-only).
    *   **Implementation:**
        *   `"cmd.cam.toolpath.contour2d": "2D Contour"`
        *   `"help.cam.toolpath.contour2d": "Generates a 2.5D profile toolpath offsetting selected edges by the tool radius."`

**Verification:**
*   Run `cargo check -p solidcraft-engine -p solidcraft-doc` to ensure struct definitions and schema derivations compile.

## Phase 2: Toolpath Algorithm & Command Execution

In this phase, we write the hostile-input-safe command that transforms the selected geometry into a valid G-Code ready polyline.

**Files to Modify/Create:**
*   `crates/engine/src/cmd/cam_toolpath_contour.rs` (New File)
    *   **Action:** Implement the `CommandSpec` for `cam.toolpath.contour2d`.
    *   **Implementation:**
        *   Declare `pub const SPEC: CommandSpec` with `.id("cam.toolpath.contour2d")`, `.icon("cam-contour")`, and mapped schemas.
        *   Implement the `run(session, params)` function.
        *   **Algorithm Steps:** 
            1. Fetch the exact BREP geometry for `target_edges` from the session document.
            2. Validate that a valid tool exists and extract its radius.
            3. Project target edges to the active CAM Setup coordinate system's XY plane.
            4. Offset the edges by `tool_radius` (using exact geometry/sketch offsetting).
            5. Generate Z-level passes based on `clearance_height`, `bottom_depth`, and `stepdown`.
        *   Return `Ok(CamContour2dOutput)` containing the ordered toolpath points.
*   `crates/engine/src/cmd/mod.rs`
    *   **Action:** Register the new `cam_toolpath_contour` module.
*   `crates/engine/src/cmd/cam_toolpath_contour_tests.rs` (New File)
    *   **Action:** Write deterministic, fast unit tests measuring output points and lengths.
    *   **Implementation:** Create a dummy rectangular body, execute the `cam.toolpath.contour2d` command, and assert the resulting total toolpath length and stepdown array match expected geometry.

**Verification:**
*   Run `cargo test -p solidcraft-engine --lib cam` to ensure toolpath geometry generation works and never panics on hostile edge inputs.

## Phase 3: UI Dialog & Browser Integration

In this phase, we integrate the new command into the `ui-egui` layer strictly using `ui_kit` containers and `theme::Tokens`. No raw egui frames or custom layouts.

**Files to Modify/Create:**
*   `crates/ui-egui/src/dialogs_cam.rs`
    *   **Action:** Create the front-end form `Contour2dDialog` that gathers user input and dispatches the command.
    *   **Implementation:**
        *   Wrap the dialog strictly in `ui_kit::Window::new("2D Contour")`.
        *   Use `ui_kit::choice_row` for tool selection (populating from the document's tool library).
        *   Use `ui_kit::expr_row` for depth parameters (`bottom_depth`, `stepdown`).
        *   Use `ui_kit::text_row` for naming the operation.
        *   On Apply/Submit, call `app.run("cam.toolpath.contour2d", params)`.
*   `crates/ui-egui/src/cam_browser.rs`
    *   **Action:** Ensure the new Contour feature populates in the CAM feature tree layout.
    *   **Implementation:** Map `CamContour2d` nodes to standard `ui_kit::tree` nodes, applying `crate::theme::Tokens::text_default()` for text.
*   `crates/ui-egui/src/viewport.rs` (or `cam_gnomon.rs`)
    *   **Action:** Add visualization for the output toolpath lines.
    *   **Implementation:** Read the polyline result from the engine state and draw it using theme tokens for CAM toolpaths (e.g., `Tokens::cam_path_cut()` and `Tokens::cam_path_link()`).

**Verification:**
*   Run `cargo xtask ui-containers` to guarantee 100% compliance with `ui_kit` rules.
*   Run `cargo xtask i18n --add-missing` and `cargo xtask lists` to ensure localization and feature lists are sorted and intact.
*   Run `cargo xtask ci` as a final check for WASM compliance (`cargo xtask wasm`), layers, and clippy warnings.
