# 1. USER INTENT & WORKFLOW GOAL
- **Exact Named View Alignment:** Ensure that creating a Named View from a Coordinate System (CS) perfectly aligns the camera so the CS +X axis points right, +Y points up, and -Z points forward, without flipping based on world orientation.
- **CS Sketch & Plane Conversion:** Fix the JSON deserialization error (`invalid type: map, expected a string`) when creating a sketch directly on a CS. Add a "Convert to Plane" option in the CS right-click context menu to generate a datum plane from the CS axes.
- **Dynamic Gnomon Live Snapping:** Make the Dynamic Gnomon interactive in `OriginSnap` and `AxisOrbit` modes by continuously tracking the cursor (without requiring a drag), highlighting geometric snap points within 20 pixels, instantly aligning to snapped geometry (origins and face normals), and utilizing ray unprojection when no snap point is nearby.

# 3. TECHNICAL IMPLEMENTATION SPEC

**CS Context Menu & Alignments (`cam_browser.rs` / `schema/sketch_create.rs`)**
- **Named View Math:** When constructing the view parameters for "Convert to Named View", set the camera pivot to `cs.origin`. Set the camera `look_dir` to `-cs.z_axis` and the `up_dir` explicitly to `cs.y_axis` to enforce roll lock.
- **Sketch Deserialization Fix:** In the "Create Sketch" action, pass the target parameter exactly as expected by the schema (e.g., `json!(cs.id)` as a string instead of a map `{"CoordinateSystem": cs.id}`). Ensure `engine` handles the ID properly to extract the CS XY plane.
- **Convert to Plane:** Add a `ui_kit::Menu` button for "Convert to Plane". When clicked, call `app.run("construct.plane", json!({...}))` with the CS origin, X, and Y axes, passing the name `"CS Plane: {cs_name}"`.

**Dynamic Gnomon Tracking & Snapping (`dynamic_gnomon.rs`)**
- **Live Event Loop:** In `dynamic_gnomon`'s update method, if the mode is `OriginSnap` or `AxisOrbit`, call `ctx.request_repaint()` to force continuous evaluation.
- **Pointer Polling:** Fetch `ui.input(|i| i.pointer.hover_pos())`. If `Some`, execute unprojection and snap logic immediately (no drag required).
- **Candidate Gathering:** Iterate through visible session B-rep (vertices, midpoints, circle centers, face centers/normals) and project their 3D coordinates to 2D using `camera.project()`.
- **Proximity Filter:** Find the closest candidate within a 20-pixel threshold radius in screen space. Draw a high-visibility highlight dot at this 2D location.
- **OriginSnap Logic:**
  - If snapped: `dg.origin = snap.3d_pos`. If snap is a face center, `dg.z_axis = snap.normal`, and orthogonalize X and Y.
  - If not snapped: Use `camera.unproject()` to cast a ray from the cursor onto a plane facing the camera passing through the initial DG origin.
- **AxisOrbit Logic:**
  - `dg.origin` remains locked.
  - If snapped: Set the active axis to `normalize(snap.3d_pos - dg.origin)`.
  - If not snapped: Set the active axis to `normalize(unprojected_cursor - dg.origin)`.
  - Apply right-hand cross products to ensure the non-active axes remain rigidly orthogonal.
- **Commit:** On primary mouse click (`ui.input(|i| i.pointer.primary_clicked())`), commit the DG state and revert to `Idle`.
